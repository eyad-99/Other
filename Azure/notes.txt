what is cosmos container
A Cosmos container in Azure Cosmos DB is the fundamental unit where your data is stored, partitioned, and scaled. It defines how items are organized, how throughput is provisioned, and how queries are executed.

🔑 What is a Cosmos Container?
Data storage unit: A container holds JSON documents (NoSQL), rows (Cassandra), graph nodes/edges (Gremlin), or tables (Table API), depending on the API you use.

Partitioning: Each container requires a partition key (e.g., /userId), which determines how data is distributed across physical partitions for scalability.

Throughput: You can assign Request Units per second (RU/s) to a container, either fixed or autoscale, to control performance and cost.

Unlimited scale: Containers automatically scale horizontally by adding partitions as data or throughput grows.

📂 Hierarchy in Cosmos DB
Element	Role	Example
Account	Top-level resource with global distribution, consistency, and security settings	mycosmosdb
Database	Logical grouping of containers	CustomerDB
Container	Stores items, defines partition key & throughput	Orders
Item	Individual record (JSON doc, row, node, etc.)	{ "orderId": 123, "amount": 50 }


⚙️ Key Features of Containers
Partition key: Critical for performance; choose a key with high cardinality and even distribution.

Provisioned throughput: Assign RU/s to a single container or share across multiple containers in a database.

Global distribution: Containers replicate across regions automatically when enabled.

Consistency levels: Queries respect the account’s consistency model (Strong, Bounded Staleness, Session, Consistent Prefix, Eventual).

bash

Items with the same partition key value always end up in the same logical partition.

what is the use of ? with string as string allow null already
In C# (and other .NET languages), the ? after a type has a very specific meaning — it’s not the same as just saying “this can be null.”

🔑 Difference Between string and string?
string: In C#, string is a reference type, so it can already hold null.

string?: This comes from the nullable reference types feature introduced in C# 8.0. It’s not about runtime behavior (strings were always nullable), but about compile-time safety.

⚙️ What string? Does
It tells the compiler: “This string may be null, so warn me if I forget to check for null before using it.”

It enables static analysis: the compiler will issue warnings if you dereference a string? without checking for null.

It’s part of the nullable annotations system that helps prevent NullReferenceException at runtime.

📂 Example
csharp
string name = "Eyad";     // Compiler assumes 'name' is never null
string? nickname = null;  // Compiler knows 'nickname' may be null

Console.WriteLine(name.Length);       // Safe
Console.WriteLine(nickname.Length);   // Warning: possible null dereference
🚀 Why Use It?
Null safety: Helps you catch potential null reference bugs at compile time.

Code clarity: Makes intent explicit — other developers know this property can be null.

Best practice: Recommended in modern C# projects, especially with ASP.NET Core, EF Core, and APIs where nullability matters.

So:

string → can be null, but compiler assumes you’ll handle it.

string? → can be null, and compiler warns you if you don’t handle it.

what is primary key in cosmos db
In Azure Cosmos DB, there is no concept of a primary key like in traditional relational databases (SQL Server, MySQL). Instead, Cosmos DB uses a partition key + item ID combination to uniquely identify each record.

🔑 How Uniqueness Works in Cosmos DB
Partition Key

A property you define at container creation (e.g., /customerId).

Determines how data is distributed across partitions.

Item ID

Every item (document/row) must have an id property.

This is a string value that uniquely identifies the item within its partition key value.

Composite uniqueness

The combination of partition key value + id is what makes an item unique in a container.

Example:

Item 1 → customerId = "C001", id = "123"

Item 2 → customerId = "C001", id = "124"

Item 3 → customerId = "C002", id = "123"

Items 1 and 3 are allowed because they have different partition key values, even though the id is the same.

📂 Example JSON Item
json
{
  "id": "123",
  "customerId": "C001",
  "name": "Eyad",
  "region": "EU"
}
Partition key path: /customerId

Partition key value: "C001"

Unique key: (customerId = "C001", id = "123")

⚙️ Key Differences vs SQL Primary Key
Aspect	SQL DB Primary Key	Cosmos DB Identifier
Definition	One or more columns marked as PK	id + partition key
Scope	Unique across entire table	Unique only within a partition key value
Enforcement	Database engine enforces PK constraint	Cosmos DB enforces uniqueness on (id, partition key)
Flexibility	Fixed schema	Schema-less JSON, but id is mandatory


✅ Summary
Cosmos DB does not have a single-column primary key.

Instead, uniqueness is enforced by the pair of partition key value + id property.

This design supports horizontal scaling and multi-tenant workloads.
