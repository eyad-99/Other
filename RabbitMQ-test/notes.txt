10- channel.BasicQos(prefetchSize: 0, prefetchCount: 1, global: false);
🔍 What it means (simple)

👉 “Give me only 1 message at a time, and don’t send another until I ACK it.”

🔹 Parameters explained
1) prefetchSize: 0
Limit based on message size (bytes)
0 = ignore size limit
👉 Almost always left as 0
2) prefetchCount: 1
Max number of unacknowledged messages allowed per consumer

👉 1 means:

Consumer gets one message
Must ACK it before receiving the next
3) global: false
false → applies per consumer
true → applies to the whole channel

👉 Usually: false

16- topic exchange vs direct exchange   

🔹 1) Direct Exchange

👉 Routes messages based on exact match of routing key

How it works
Producer sends message with a routing key (e.g., "order.created")
Exchange delivers it only to queues bound with the same exact key
🧠 Example
Routing Key: "order.created"

Bindings:
Queue A → "order.created"   ✅ gets message
Queue B → "order.updated"   ❌ ignored
🔹 2) Topic Exchange

👉 Routes messages based on pattern matching

Uses wildcards
Much more flexible
🔹 Wildcards in topic exchange
* → matches one word
# → matches zero or more words
🧠 Example
Message:
Routing Key: "order.created.eu"
Bindings:
Queue A → "order.*"          ❌ (only 2 words expected)
Queue B → "order.#"          ✅ (matches anything after order)
Queue C → "*.created.*"      ✅ (pattern match)

Yes — you absolutely still need a binding between the queue and the exchange.

👉 Routing keys alone are not enough.








18-   can a queue connect to more than one exchange

Yes — a queue can be bound to multiple exchanges, and this is a very normal pattern in RabbitMQ.

🔹 How it works

A queue doesn’t “connect” directly — it gets bound to exchanges.

👉 You can create multiple bindings like this:

channel.QueueBind("my_queue", "exchange_A", "key1");
channel.QueueBind("my_queue", "exchange_B", "key2");
🧠 What this means

Your queue will receive messages from:

exchange_A (when routing key = "key1")
exchange_B (when routing key = "key2")
