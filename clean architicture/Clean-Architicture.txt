1. Operation Script (Transaction Script)
An operation script implements a use case as a procedure that contains the steps and business rules needed to complete it.
For example, in a .NET e-commerce application:
public class PlaceOrderService
{
    public async Task PlaceOrder(int orderId)
    {
        var order = await _repository.GetById(orderId);

        if (order.Total <= 0)
            throw new Exception("Invalid total");

        order.IsConfirmed = true;

        await _repository.Save(order);
    }
}


The service contains both the workflow and the business rule.
- Application logic: Load the order and save it.
- Business logic: Check the total and confirm the order.
This is simple and often suitable for CRUD applications or use cases with straightforward rules.
2. Domain Facade
A Domain Facade provides a simplified interface to domain operations. It delegates the actual business behavior to domain objects or domain services.
For example:
public class Order
{
    public decimal Total { get; private set; }
    public bool IsConfirmed { get; private set; }

    public void Confirm()
    {
        if (Total <= 0)
            throw new InvalidOperationException("Invalid total");

        IsConfirmed = true;
    }
}


The application service coordinates the use case:
public class PlaceOrderService
{
    public async Task PlaceOrder(int orderId)
    {
        var order = await _repository.GetById(orderId);

        order.Confirm();

        await _repository.Save(order);
    }
}


Here, the application service coordinates the operation, while the Order entity owns the rule that protects its state.

Ports and Adapters is another name for Hexagonal Architecture. They are not two different concepts: ports and adapters are the main building blocks of Hexagonal Architecture.
1. What is Hexagonal Architecture?
Hexagonal Architecture is an architectural style introduced by Alistair Cockburn. It aims to keep your application's core business logic independent of external technologies, such as databases, web APIs, and user interfaces.
It is called hexagonal because diagrams often represent the application core as a hexagon. The six sides are just illustrative; the architecture does not require exactly six components.

Port
A port defines a way to interact with the application or a capability the application needs. In .NET, it is often represented by an interface.
For example:
public interface IOrderRepository
{
    Task<Order?> GetByIdAsync(int id);
    Task SaveAsync(Order order);
}


The application needs to load and save orders, but it doesn't specify how the data is stored.
Adapter
An adapter implements or uses a port to connect the application to a specific technology.
public class SqlOrderRepository : IOrderRepository
{
    private readonly AppDbContext _db;

    public SqlOrderRepository(AppDbContext db)
    {
        _db = db;
    }

    public Task<Order?> GetByIdAsync(int id)
        => _db.Orders.FindAsync(id).AsTask();

    public async Task SaveAsync(Order order)
    {
        _db.Orders.Update(order);
        await _db.SaveChangesAsync();
    }
}


Here, SqlOrderRepository is an adapter that connects the application to SQL Server through EF Core.

4. How does this relate to Clean Architecture?
They share a major principle: the core application should not depend directly on external infrastructure details.
- Hexagonal Architecture explains the system in terms of ports and adapters.
- Clean Architecture organizes the system into layers and emphasizes the dependency rule.
- Both can use interfaces, dependency inversion, and infrastructure implementations.
You can implement Clean Architecture using ports and adapters; they are compatible approaches, not competing architectures.
