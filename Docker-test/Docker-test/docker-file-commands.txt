| Command       | What it does                   | Simple meaning                         |
| ------------- | ------------------------------ | -------------------------------------- |
| `FROM`        | Sets base image                | “Start from this OS/runtime”           |
| `WORKDIR`     | Sets working directory         | “Go to this folder inside container”   |
| `COPY`        | Copies files into image        | “Move files from PC → container”       |
| `RUN`         | Executes commands during build | “Run this while building image”        |
| `ARG`         | Build-time variable            | “Temporary variable for build only”    |
| `ENV`         | Environment variable           | “Set config inside container”          |
| `EXPOSE`      | Declares ports                 | “App listens on this port (info only)” |
| `ENTRYPOINT`  | Main startup command           | “What runs when container starts”      |
| `CMD`         | Default command                | “Fallback command if none given”       |
| `COPY --from` | Copy from another stage        | “Move files between build stages”      |

Cluster → A set of machines (nodes) managed by Kubernetes. Contains a control plane and worker nodes.

Node → A worker machine (VM or physical) that runs pods. Each node has a kubelet and container runtime.

Pod → The smallest deployable unit in Kubernetes. A pod can contain one or more containers that share storage and networking.

Deployment → Defines how many replicas of a pod should run and manages rolling updates/rollbacks.

Service → Provides a stable network endpoint (IP/DNS) to access pods, with built‑in load balancing.

Namespace → Logical partitioning of a cluster to isolate resources (e.g., dev, staging, prod).

ConfigMap → Stores non‑sensitive configuration data for pods.

Secret → Stores sensitive data (passwords, tokens, keys) securely.

Ingress → Manages external access to services, typically HTTP/HTTPS routes.
