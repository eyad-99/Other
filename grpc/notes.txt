-HTTP/2 uses a binary protocol instead of text. Data is split into small units called frames. Frames belong to streams,
 and multiple streams can share the same TCP connection. This allows multiplexing, better performance, and more efficient communication than HTTP/1.1.
-Converting data to binary and splitting it into frames does add a small processing cost. However,
 HTTP/2 is faster because framing enables multiplexing, header compression, and the use of a single TCP connection for many requests.
 The performance gains from reduced network latency and better connection utilization are much larger than the small overhead of framing.

 -HTTP/2 uses a binary format because binary messages are easier and faster for machines to parse, have a strict structure with less ambiguity, and enable features such as multiplexing and efficient framing.
 Although there is a small encoding/decoding cost, it is negligible compared to network latency, and the benefits greatly outweigh the overhead.
